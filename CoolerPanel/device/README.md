# CoolerPanel firmware: device

The real-hardware platform layer for the **Waveshare ESP32-S3-Touch-LCD-4B**
("Smart 86 Box": 4-inch 480×480 ST7701 RGB panel, GT911 touch,
ESP32-S3-WROOM-1-N16R8). It reuses [`shared/`](../shared/) unchanged (the
portable UI and model validated by the desktop simulator) plus the portable
config core in [`config/`](../config/).

## Status: built and running on hardware

Boot ("Cooler32" splash) → captive-portal setup (first boot / touch-hold /
Wi-Fi failure) → Wi-Fi + NTP → MQTT over TLS to the cooler broker as
the panel's own login (private CA compiled in) → live Trend / Settings / Detail screens.
Night dimming 23:00–07:00 local with touch wake.

## Build & flash

Install [PlatformIO](https://platformio.org/), plug the board into the
**USB-to-UART** Type-C port, then:

```bash
tools/import_cooler_broker.sh   # from the repo root: broker, login and CA -> config/cooler_defaults.h
cd device
tools/gen_assets.sh             # once: fonts, logo, Wi-Fi seed header
pio run -t upload               # build + flash (pioarduino, Arduino core 3.2.0)
pio device monitor              # 115200 baud serial log
```

`gen_assets.sh` needs node (`npx lv_font_conv`) and python3 with Pillow + `pypng`
(see the script header). If a `panel_seed.json` exists at the repo root it emits
`src/assets_gen/config_seed.h` (Wi-Fi only, **git-ignored, real credentials**)
as the first-boot NVS seed. The MQTT broker, login, topic base and CA come from
`config/cooler_defaults.h` (git-ignored), generated by
`tools/import_cooler_broker.sh`.

## First boot / setup portal

An unconfigured device (or one whose Wi-Fi fails for 15 s) boots into
**setup mode**: it opens a WPA2 access point `CoolerPanel-Setup-XXXX` with a
per-device random password, both shown on the panel along with tap-to-show
QR codes (join the Wi-Fi / open `http://192.168.4.1`). Joining pops a
captive setup page pre-filled with the seeded config — pick your Wi-Fi,
check the MQTT settings, hit **Save & Restart**. Saved passwords are never
echoed back into the form (`********` means "keep stored value").

**Reconfigure anytime**: hold a finger on the glass while the device boots
(keep it there through the splash) — it re-enters the portal even with a
valid config. **Factory Reset** in the portal wipes NVS; the next boot
reseeds from the compiled-in defaults and returns to setup mode.

## Hardware notes (hard-won — read before touching display/flash code)

- Board config source of truth: Waveshare's demo package + BSP
  (`waveshare/esp32_s3_touch_lcd_4b`) — pins/timings are documented at the
  top of `src/display_gfx.cpp`. The ST7701's 3-wire SPI init runs through a
  TCA9554 I2C expander (hence Arduino_GFX, which supports that; LovyanGFX
  does not), and the panel needs the BSP's vendor init sequence — the
  generic `st7701_type1` table has wrong power/pump registers for it.
- **The backlight (GPIO4 PWM) is active-low** — full duty = dark panel.
- **Never write flash (NVS) while the panel scans.** The RGB vsync ISR calls
  flash-resident GDMA code in the prebuilt Arduino core, so a flash write
  during scan-out panics (`Cache disabled but cached memory region
  accessed`). All NVS writes happen before `display_init()`; runtime config
  changes go through `config_request_save()/_clear()` (staged in RTC RAM,
  applied on the next boot, pre-display). Wi-Fi runs with
  `WiFi.persistent(false)` for the same reason.
- The boot touch-hold is sampled from the *previous* session's GT911 before
  this boot's touch reset — resetting the controller re-baselines it with a
  resting finger included, making the finger invisible afterwards.

## Night dimming timezone

`ntp.cpp` defaults to `EST5EDT` (America/Toronto) for the 23:00–07:00 dim
window; override with `-DLLMMON_TZ='"<posix tz>"'` (macro name kept from the panel's origin) in `platformio.ini`.
Epoch/aging logic is UTC and unaffected.
